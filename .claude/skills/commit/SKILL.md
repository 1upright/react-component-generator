# Commit 스킬

변경사항을 자동으로 분석하고, 컨벤션에 맞는 커밋 메시지를 작성한 후 사용자 승인을 받아 커밋하는 스킬입니다.

## 절차

### 1단계: 변경사항 분석
```bash
git status
git diff
git diff --cached
```

위 명령어로 현재 워킹 트리의 모든 변경사항(staged, unstaged, untracked)을 확인합니다.

### 2단계: 논리적 단위로 분류

변경사항을 다음 기준으로 분류합니다:

- **기능 추가** (feat): 새로운 기능이나 페이지 추가
- **버그 수정** (fix): 기존 버그 해결
- **리팩토링** (refactor): 기능 변화 없이 코드 구조 개선
- **문서/설정** (chore): README, package.json, 환경 설정, 의존성 업데이트 등

**같은 타입의 변경사항을 그룹화합니다.** 예를 들어, 버그 수정 여러 개는 한 커밋으로 묶을 수 있지만, 버그 수정과 새 기능은 분리합니다.

### 3단계: 한국어 커밋 메시지 작성

각 논리적 단위마다 이 형식의 메시지를 작성합니다:

```
<타입>(<범위>): <요약>
```

**타입**: `feat`, `fix`, `refactor`, `chore`  
**범위** (선택): 변경이 영향을 미치는 부분 (예: `auth`, `dashboard`, `config`)  
**요약**: 한국어로 작성, 현재형, 50자 이내

### 예시

```
feat(auth): JWT 기반 인증 구현
fix(dashboard): 차트 데이터 로딩 오류 수정
refactor: 불필요한 의존성 제거
chore: 패키지 버전 업데이트
```

## 동작 방식

1. 변경사항을 분석하고 커밋할 파일들을 자동으로 staging합니다.
2. 논리적 단위별로 커밋 메시지를 작성하고 즉시 실행합니다.
3. 커밋 완료 후 결과를 사용자에게 보고합니다.

## 주의사항

- **민감 정보 제외**: `.env`, `credentials.json` 등 민감한 파일이 포함되면 경고합니다.
- **용량이 큰 파일**: 바이너리나 lock 파일 추가 시 사용자에게 확인합니다.
- **이미 staged된 파일**: `git diff --cached` 출력도 함께 검토합니다.
